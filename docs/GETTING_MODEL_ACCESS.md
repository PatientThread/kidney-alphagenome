# Getting AlphaGenome model access

Verified live 13 September 2026. Read §0 first: you may not need any of this.

---

## 0. Do you actually need it?

**Probably not for Paper 1.** The central result does not depend on running the
model. It is that kidney is down-weighted 7.71-fold in the published average,
has 59 fine-mapped positives against a median of 616 and a maximum of 1,756, and
is the smallest tissue at all 36 threshold settings tested. From that the
confidence interval is too wide to interpret at any true correlation value. That
argument is complete, and no prediction changes it.

Getting access is worth doing anyway for two reasons: Paper 2 on APOL1 will need
predictions, and having run the model makes the Paper 1 discussion concrete
rather than purely theoretical. But it is not on the critical path, so do it when
convenient rather than before writing.

---

## 1. The blocker to know before you start

**A personal Google account is required. Google Workspace and Enterprise
accounts cannot generate a key.** This is the most commonly reported failure and
the support team confirms it.

Your usual address is Outlook, so a personal Gmail account is needed. Any
existing personal Gmail works; a new one takes two minutes.

Do not use an address tied to Patient Thread, Scira or Lawrence Medical. That is
not just a technical point. The terms restrict use to non-commercial
organisations, so this must be accepted in a personal, academic capacity. Using a
company address would be the wrong signal on the wrong document.

---

## 2. Route A, the API key. Easiest, right for Paper 2.

1. Go to **https://deepmind.google.com/science/alphagenome**
2. Click **Get API key**. You will be asked to sign in and accept the terms at
   `deepmind.google.com/science/alphagenome/account/terms`.
3. Sign in with the **personal Gmail**.
4. Accept the Model Terms of Use.
5. Copy the key. Store it outside the repository, for example in
   `~/.alphagenome`, and never commit it.
6. Install:
   ```bash
   git clone https://github.com/google-deepmind/alphagenome.git
   pip install ./alphagenome
   ```

**Known failure modes, all reported by other users:**

| Symptom | Cause | Fix |
|---|---|---|
| Key generation fails silently | Workspace or Enterprise account | Use a personal Gmail |
| Repeated failure on a personal account | Stale session | Refresh, clear cache, or try another personal account |
| Key stops working later | A linked Google Cloud project was deleted | Do not tidy up Cloud projects after setup |
| Cannot create key at all | Cloud project quota reached | Free up a project slot |

Support address: alphagenome@google.com

**Scale.** The documentation says the API suits analyses "requiring 1000s of
predictions" and is "likely not suitable for large scale analyses requiring more
than 1 million predictions". Our benchmark set is 32,818 variants, which is
inside that range but not comfortably.

---

## 3. Route B, the Atlas. Better for our 32,818 variants.

Same sign-in and same terms. The precomputed Atlas holds scores for roughly nine
billion single-nucleotide variants plus over a hundred million insertions and
deletions observed in biobanks, and the documentation states it "will typically
have a larger query rate" than live prediction.

Two constraints that matter for us. Atlas scores are computed against the GRCh38
reference only, and it enumerates the three alternative bases at each position,
so **it contains no non-reference-to-non-reference substitutions**. And Atlas
outputs are non-commercial and explicitly must not be used to train other models.

---

## 4. Route C, run it locally. The fallback, and the one with the cleanest code licence.

The support team's own suggestion when a key cannot be issued.

- Code: `github.com/google-deepmind/alphagenome_research`, **Apache 2.0**,
  includes the full model implementation in JAX plus variant scorers.
- Weights: `huggingface.co/google/alphagenome-all-folds` (also fold-1, fold-2,
  fold-3), and on Kaggle. **Gated**: a Hugging Face account is needed, and the
  Model Terms of Use must be accepted before download.
- Training, validation and test data are released as TFRecords, but note the
  released dataset **excludes the GTEx tissue portion** for licensing reasons.

## 5. What you are agreeing to, in plain terms

Quoted from the model card and README:

> "The model parameters are restricted to non-commercial use by non-commercial
> organizations (e.g., universities, non-profits, research institutes, and
> journalism)... It must not be used for any commercial activities or on behalf
> of commercial entities."

> "outputs generated by AlphaGenome and other information provided in
> AlphaGenome Atlas are for non-commercial use only and should not be used for
> the training of other machine learning models."

> "Predictions are for theoretical modelling and research purposes only. They
> must not be used for clinical decision-making or relied upon for medical or
> other professional advice."

Fine-tuned derivatives inherit the same restriction.

**The consequence for the wider programme, and it is the important one.** None of
this touches the separate commercial route. The model *code* is Apache 2.0, so
training your own model from scratch on your own data, using the published
architecture, needs no permission from DeepMind at all. What is barred is using
their weights, their interface, or their outputs. Keep those two lanes visibly
separate: this project is personal academic work, and anything commercial starts
from the Apache-2.0 code and your own data.
